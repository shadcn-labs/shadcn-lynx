# Introduction

shadcn-lynx is an open-code component registry for ReactLynx. It applies shadcn/ui's neutral visual language to every component exported by `@lynx-js/lynx-ui`, then copies the source into your app so you own the implementation.

## Architecture

- **Behavior:** headless `@lynx-js/lynx-ui` primitives provide state, gestures, controlled and uncontrolled modes, and cross-platform behavior.
- **Appearance:** Tailwind utilities, semantic color tokens, `cn()`, and CVA reproduce shadcn/ui's surfaces, typography, focus states, sizes, and variants.
- **Platform:** components render Lynx elements such as `view`, `text`, `image`, `list`, and `scroll-view` rather than browser DOM elements.
- **Distribution:** the CLI copies source from the registry; there is no runtime shadcn-lynx package to lock your app into.

## Documentation stack

The site remains on Rspress. The official lynx-ui documentation uses the same stack, and `@lynx-js/go-web` ships a dedicated Rspress adapter for source tabs, Lynx bundles, web bundles, and static previews. Moving to Next.js would replace working Lynx-specific integration without adding required functionality.

## How it works

1. Start with a ReactLynx application built by Rspeedy.
2. Run `npx shadcn-lynx init` to configure aliases, utilities, and theme tokens.
3. Run `npx shadcn-lynx add <component>`.
4. Import the copied source from `@/components/ui` and customize it as application code.

## Lynx constraints

Lynx is web-like but has no DOM. Text belongs in `text`, general layout uses `view`, long virtual collections use `list`, and bounded scrolling uses `scroll-view`. Event handlers and high-frequency gesture work must respect ReactLynx's background-thread and Main Thread Script boundaries.
